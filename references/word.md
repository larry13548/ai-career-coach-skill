# Word 生成与视觉检查

## 交付前的决定
直接生成可编辑Word初版，交付后接受修改，不要求完整正文先获确认。先按[模板目录](templates.md)提供样式选择；有选择沿用，无偏好或用户希望直接生成则默认单栏。资料不齐不阻塞：缺字段填写待补充，缺照片保留位置标照片待上传。

可用平台原生文档工具，也可运行内置脚本。脚本依赖Python 3及python-docx（requirements.txt），不依赖本地固定路径或联网。宿主没有脚本/安装能力时用实际可用的原生工具执行相同要求；若没有Word生成能力，说明只能交付正文，不伪装已生成文件。

## 新建 Word
从用户提供的资料及据此优化的初稿整理JSON，禁止混入模板示例内容。无需confirmed字段；旧字段兼容但不控制生成。缺少姓名、联系方式等用待补充；没有内容的经历模块删除。

```json
{
  "name": "用户提供的姓名",
  "target": "用户提供的目标岗位",
  "contact": ["用户提供的联系方式"],
  "sections": [
    {"title": "工作经历", "column": "main", "entries": [
      {"heading": "公司 | 岗位", "period": "起止年月",
       "detail": "必要的背景介绍",
       "bullets": ["基于用户材料整理的行动与成果"]}
    ]},
    {"title": "教育背景", "column": "sidebar", "entries": [
      {"heading": "学校 | 专业 | 学历", "period": "起止年月"}
    ]}
  ]
}
```

调用 `python scripts/resume_docx.py build resume.json output.docx --layout single-column`。
- layout为single-column/sidebar/banner。使用侧栏时明确把教育、技能等短模块设为column:sidebar；其他正文为main。其他版式按JSON模块顺序排列。
- 条目支持heading、period、detail、bullets，均仅包含用户提供的文字；内容由AI提炼，工具不补写经历。
- 可选photo为用户提供的照片文件路径（相对路径以JSON位置为基准）；不生成或猜测本人照片。
- 可选visual配置如 `{"accent":"FFC000","section_markers":true,"corners":true}` 可重建黄色标记和简单边角。仅在与来源一致或用户选择时启用。这是近似重建，不是通用PDF保真转换；图标内容和不同页角位置仍要单独检查。
- section.icon可指向提取的原始模块图标，保持图标内容；不要用圆点冒充原图标。visual.backgrounds可指定原始装饰图片，格式为 `[{"path":"原装饰.png","x_cm":0.5,"y_cm":0.5,"width_cm":3,"scope":"first"}]`，scope为first/rest/all；保持原比例，坐标须基于原页观察，逐页复核。所有图片路径可相对于输入JSON。背景放在可编辑正文后方，不能用含正文的整页截图当背景。
- 可选section.page_break_before:true在模块前分页，仅在渲染后发现不理想分页时使用；更长经历可拆成“公司经历（续）”并核对无重复丢失。
- 脚本不覆盖已存在的输出文件，修改后换版本名。

内置模板统一：微软雅黑，正文11磅、固定18磅行距、段后9磅，模块标题前22磅、后9磅。没有微软雅黑时告知字体替代；不得把替代字体的截图认作已验证微软雅黑效果。较长内容允许自然分页，不能缩行距硬塞1—2页。需要压缩内容时先与用户确认删减。

## 保留原简历视觉
- 原Word：优先原文件副本局部改写。`inspect`给出正文段落编号及复杂标记。准备 `{"edits":[{"index":0,"expected":"原文字","replacement":"优化后的文字"}]}` 并用 `patch`。段落索引包括表格，不含页眉页脚。原文不一致则停止重读；脚本保留非修改部分及插图，对包含图形、域、链接等复杂段落拒绝纯文本替换。普通混合加粗段落修改后需恢复必要局部强调。
- 原PDF/图片：先观察每页版式并列出要保留的视觉元素（照片、边角、图标、配色、层级、栏结构）。正文重建为文字；对照片/背景/图标使用原始素材或宿主可用的提取工具，按原比例放置。不可用整页图片替代可编辑正文。
- 简单圆点不能算保留原有图标；没有背景元素的样例不能证明背景迁移通过。内置生成器处理三种布局、照片、原图标、按坐标放置的原装饰图片和简单矢量边角；素材提取与坐标测量仍需宿主工具，复杂跨栏布局需宿主文档工具处理，完成不了就指出具体未保留项。
- 内容有新增时优先合理续页和续接提示，避免同段经历在新页无上下文。视觉效果有差异时报告，不把替代模板默认算作达标。

## 交付检查
1. 生成后重新读取所有正文段落（含表格），与用户资料及优化稿核对：姓名、联系方式、日期、数字、公司、学历、用户贡献和所有内容是否保留。字体/文字结构检查不能替代实际分页检查。
2. 用宿主实际可用的Word预览或渲染工具查看每页：无乱码、截断、重叠、标题孤立、意外空白页；检查内容增加后分页与模块间距。无法预览就标“排版未验证”，不可声称通过。
3. 对照所选模板或原文件：版式、照片、图标、背景、配色逐项检查。制作与视觉验收分开，不能只看有.docx后缀。
4. 输出真实文件链接及简短检查结果。用户有存疑事实时另列待确认清单，不擅自修改指标。照片、姓名等私人数据不写入公开测试报告。

## 用户下载的模板
T01—T09是保留原结构的Word源模板，路径与预览见templates.md。三种layout脚本不适用于这些文本框模板；须用宿主支持文本框、浮动图片和表格的文档工具编辑原模板副本，保留版式并清除所有示例文字（含页眉、页脚、文本框和兼容分支）。脚本patch遇复杂对象会拒绝，不能跳过错误谎称已套用。无法编辑所选模板时明确说明具体限制并提供可用模板初版，不将替代文件冒称所选样式。
缺照片时可保留模板示例照片，但必须在图上或紧邻处标“示例照片·待上传替换”；不可将第三方照片当作用户照片。缺文字字段填待补充；不为填满模板虚构内容。
